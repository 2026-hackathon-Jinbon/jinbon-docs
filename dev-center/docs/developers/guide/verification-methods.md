# URL·파일 검증 차이

**파일 검증은 내가 가진 파일을, URL 검증은 서버가 게시물 주소에서 내려받은 파일을 분석합니다.** 이후에는 같은 [검증 과정](/developers/flows/video-verify)을 거칩니다. 두 방식 모두 로그인 없이 이용할 수 있습니다.

## 어떤 파일을 비교하나요?

| 구분 | 파일 직접 검증 | URL 검증 |
|---|---|---|
| 입력 | 기기에 있는 영상 파일 | 지원 플랫폼의 영상 주소 |
| 분석할 파일 확보 | 사용자가 업로드 | 서버가 URL 검사 후 다운로드 |
| 이용 채널 | 웹·iOS 앱 | 웹·Chrome 확장·카카오톡 챗봇 |
| 주의할 점 | 메신저나 편집 앱을 거치면 파일이 달라질 수 있음 | 플랫폼이 재압축한 파일일 수 있고, 접근 제한 시 다운로드 실패 |

URL은 영상 파일을 가져오는 데 사용합니다. **주소나 게시물 계정이 같다는 이유로 승인하지 않습니다.** URL을 사전에 등록할 필요는 없지만, 비교할 영상은 진본에 등록되어 있어야 합니다.

웹의 URL 입력은 YouTube·Instagram·TikTok·X·Vimeo를 대상으로 합니다. Chrome 확장은 YouTube·Instagram에 검증 버튼을 제공합니다. 파일 크기, 허용 호스트, 다운로드 제한 등 연동 조건은 [검증 API](/developers/api/verify#input-limits)를 참고하세요.

## 같은 영상인데 결과가 다른 이유

대변인실이 `발표.mp4`를 등록하고 보증서까지 연결했다고 가정해 보겠습니다.

| 제출한 대상 | 확인 방식 |
|---|---|
| 등록했던 파일 그대로 | 파일 해시가 같으면 **파일 정확 일치** |
| YouTube 게시물 URL | 내려받은 사본의 해시가 다르면 **영상·음성 비교** |
| 그 사본을 파일로 업로드 | URL에서 가져온 파일과 같은 비교 기준 적용 |

플랫폼은 영상을 게시하면서 코덱·해상도 등을 바꿀 수 있습니다. 그래서 같은 장면이어도 파일 해시는 달라집니다. 파일 이름만 바꾸고 내용은 그대로라면 해시는 바뀌지 않습니다.

어느 방식이든 등록 증거까지 유효해야 진본으로 승인됩니다.

## 풀 영상에서 일부만 잘라냈다면 {#extracted-clips}

**등록된 풀 영상의 어느 구간에 클립이 대응하는지 찾습니다.** 풀 영상이 등록되어 있다면 클립을 별도로 등록할 필요는 없습니다. 클립 파일과 클립 게시물 URL 모두 같은 기준으로 비교합니다.

예를 들어 **10분 영상의 2:10~2:40을 잘라낸 30초 클립**이라면:

1. 대표 화면 지문으로 비슷한 등록 영상을 찾습니다.
2. 클립의 영상·음성 지문을 등록 영상의 지문 위에서 각각 **1초 단위로 이동**시키며 가장 잘 맞는 위치를 찾습니다.
3. **제출한 클립의 구간 수**를 기준으로 대응 비율을 계산합니다.
4. 영상·음성 비교와 등록 증거 확인을 통과하면 `SIMILAR_MATCH`로 승인하고 원본 대응 구간을 반환합니다.

| 비교 항목 | 예시 |
|---|---|
| 영상 | 클립의 30개 구간 중 29개 대응 → 약 96.7% |
| 음성 | 클립의 30개 구간 모두 대응 → 100% |
| 대응 위치 | 영상·음성 모두 등록 영상의 2:10에서 시작 |
| 결과 안내 | 해당 범위에 대응하면 ‘등록 영상의 2:10~2:40 구간’ 표시 |

위 예시의 영상 대응 비율은 **29/30**입니다. 풀 영상 600초 중 30초라는 이유로 5%로 계산하지 않습니다. 승인에 필요한 비율·순서·동일한 원본 시점 조건은 [영상·음성 비교 기준](/developers/flows/video-verify#match-criteria)을 참고하세요. 승인되어도 생략한 앞뒤 맥락까지 보증하지는 않습니다.

### 짧은 클립을 놓칠 수 있는 이유

- **후보 검색:** 풀 영상과 클립에서 각각 16개 대표 화면을 뽑습니다. 같은 장면이 충분히 포함되지 않으면 구간 비교 전에 `NOT_REGISTERED`로 끝날 수 있습니다.
- **시간 정렬:** 비교 위치를 1초 단위로 옮깁니다. 2:10.4부터 자른 클립처럼 샘플 시점이 어긋나면 대응 비율이 낮아질 수 있습니다. 인접 프레임 비교가 모든 시작 시점의 차이를 보완하지는 못합니다.

따라서 등록 영상에서 잘라냈더라도 모든 클립을 찾아내거나 승인하는 것은 아닙니다.

## 다운로드 실패와 미등록은 다릅니다 {#download-failure}

| 결과 | 뜻 | 확인할 것 |
|---|---|---|
| **다운로드 실패** · `VF002` | 비교할 파일을 확보하지 못한 요청 오류 | 접근 가능한 URL인지 확인하거나 가진 파일로 검증 |
| **등록 기록 없음** · `NOT_REGISTERED` | 분석했지만 등록 후보를 찾지 못함 | 등록 여부와 제출 영상의 차이 확인 |

허용 플랫폼이어도 비공개·삭제·접근 제한 때문에 다운로드가 실패할 수 있습니다. 미등록 결과는 실제 미등록 외에 후보 검색 실패로도 나올 수 있습니다. 나머지 판정은 [검증 결과 읽는 법](/developers/guide/verification-results)을 참고하세요.
