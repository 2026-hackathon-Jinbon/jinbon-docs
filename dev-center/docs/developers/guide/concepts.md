# 핵심 개념

진본은 **영상이 일치하는지 비교할 지문**과 **누가 언제 등록했는지 확인할 증거**를 함께 사용합니다.

## 지문: 영상을 비교하는 특징값

| 지문 | 계산 대상 | 용도 |
|---|---|---|
| **파일 해시** · `fineHash` | 파일 전체의 SHA-256 | 정확히 같은 파일인지 확인 |
| **대표 화면 지문** · `perceptualHash` | 영상 전체에서 뽑은 화면의 특징 | 비슷한 등록 후보 검색 |
| **영상 구간 지문** | 시간대별 대표·인접 프레임의 특징 | 등록 영상의 대응 구간 찾기 |
| **음성 구간 지문** | 시간대별 음성의 특징 | 음성도 같은 구간에 대응하는지 확인 |

재압축하면 파일 해시는 달라질 수 있어 화면·음성 지문을 추가로 비교합니다. 지문 형식과 추출 간격은 [검증 과정](/developers/flows/video-verify#candidate-search)에 정리되어 있습니다.

## 블록체인: 등록 사실을 확인할 기록

파일 해시와 대표 화면 지문을 합쳐 등록 대표값인 `merkleRoot`를 만듭니다.

```text
merkleRoot = SHA-256(perceptualHash || fineHash)
```

블록체인에는 이 대표값을 기준으로 등록자 DID, 서버 서명, 시각·활성 상태를 기록합니다. 영상·음성 구간 지문은 대표값에 포함되지 않습니다. 서버 서명은 HMAC이며 등록자의 DID 개인키 서명과는 다릅니다. [실제 검증 범위](/developers/flows/video-verify#registration-evidence)도 함께 확인하세요.

## DID와 VC: 등록자와 보증서

**DID**는 Wallet이 생성하는 식별자입니다. 진본은 본인확인한 계정에 Wallet DID를 연결하고, 영상을 등록할 때 그 DID를 기록합니다.

**VC**는 검증 가능한 디지털 보증서입니다. 등록자 DID, 영상 대표값, 등록 시점, 블록체인 트랜잭션을 묶어 특정 영상의 등록 사실을 증명합니다. 검증할 때는 보증서 자체의 유효성과 **해당 영상의 보증서인지**를 함께 확인합니다. API의 `vcClaimsBound`가 이 등록 정보 일치 여부를 나타냅니다.

| 비슷한 이름 | 구분 |
|---|---|
| 회원 권한 `ISSUER` | 영상을 등록할 수 있는 회원 |
| Open DID Issuer | VC를 발급하는 서버 |
| `issuerDid` | 영상 등록자 DID |
| `vcIssuerDid` | 보증서 발급기관 DID |

## 무엇을 어디에 저장하나요?

| 위치 | 저장하는 정보 |
|---|---|
| **DB** | 비교용 지문, 등록자·제목·시점, 트랜잭션, VC 연결 정보와 서명된 VC 원문 |
| **블록체인** | 등록 대표값, 등록자 DID, 서버 서명, 시각·활성 상태 |
| **앱 Wallet** | 발급받은 VC |
| **Redis** | 재사용 가능한 검증 결과 |
| **서버 임시 파일** | 분석용 영상. 처리 후 정리하며 장기 보관하지 않음 |

구간 비교 결과의 `coverage`, `bestOffsetMs` 등은 [검증 API의 응답 필드](/developers/api/verify#segment-result)에서 확인할 수 있습니다.
