# 진본 v5 발표 대본 및 영상 삽입 안내

[편집 중인 Google Slides](https://docs.google.com/presentation/d/1fTU6vMKmdvcJn46lVtZZKlqY6yiQ5m5CHmNs-9ochv0/edit)

## 발표 시간

발표 7분 40초와 전환 여유 20초를 계획했습니다. 시연 영상은 120초입니다. 실제 소요 시간은 영상 삽입 후 리허설로 확인합니다.

2페이지는 제출용 요약서이며 발표에서는 설명 없이 넘깁니다. 13~15페이지는 질의응답용 숨김 부록입니다.

## 시연 영상 삽입

- 대상: 물리적 6페이지, Google Slides 내부 ID `p10`.
- 영상: 16:9, 권장 1920×1080, 최종 120초.
- 위치: 왼쪽 40pt / 위 139pt / 너비 650pt / 높이 365.625pt.
- 검은 배경 `p10_i233`을 기준으로 영상을 맞춥니다. 안내 텍스트 `p10_i234`, `p10_i235` 두 개는 제거합니다. 영상으로 가려지지 않는 배경은 정리합니다.
- 오른쪽 세 단계 설명은 유지합니다. 재생 시 발표자가 영상 내레이션과 겹쳐 말하지 않습니다.
- Google Slides에서는 영상을 Drive에 올린 뒤 ‘삽입 → 동영상’으로 연결합니다. PowerPoint에서는 로컬 동영상 파일을 삽입하고 저장합니다.
- 최종 장면·자막·내레이션은 같은 폴더의 `진본_v5_시연영상_스토리보드.md`를 따릅니다.

정상본·음성 교체본의 실제 판정 확인과 VC 발급 전후 녹화는 발표자가 준비합니다. 결과 화면에는 측정한 응답을 사용합니다.

이 안내의 링크와 객체 ID는 v5 기준입니다. 이전 v4 문서의 삽입 안내 대신 사용합니다.

## 페이지별 발표 대본

### 1페이지 · 표지

**0:00–0:20 / 20초**

안녕하세요, 타닥타닥 팀입니다. 진본은 본인확인된 등록 영상과 공유된 영상을 비교하는 서비스입니다. 누가 등록했는지, 무엇과 일치하는지, 그 근거가 유효한지를 함께 확인합니다.

### 3페이지 · 팀

**0:20–0:35 / 15초**

저희는 백엔드 김다연, 프론트엔드 송승희로 구성된 타닥타닥 팀입니다. 신원 확인부터 영상 등록, Wallet 보증서와 공개 검증까지 하나의 흐름으로 연결했습니다.

### 4페이지 · 문제

**0:35–1:10 / 35초**

가상 도시 새빛시의 시장이 청년 월세 지원을 계속하겠다고 발표했다고 가정해 보겠습니다. 그런데 같은 화면에 지원을 중단한다는 음성이 담긴 영상이 전달됩니다. 시민은 어느 발표와 같은지 확인하고 싶고, 기관은 같은 근거로 응답할 수단이 필요합니다. 진본은 발표자가 사전에 남긴 등록 영상을 비교 기준으로 연결합니다.

### 5페이지 · 사용 흐름

**1:10–1:40 / 30초**

등록자는 모바일 신분증으로 본인확인을 하고, 등록자를 식별하는 디지털 식별자인 DID와 연결합니다. 영상을 등록하면 지문을 체인에 기록하고 등록 보증서인 VC를 받습니다. 이후 기존 SNS에 게시하면, 시민은 크롬이나 웹, 카카오톡에서 확인합니다. VC 발급까지 완료해야 인증할 수 있습니다.

### 6페이지 · 시연

**1:40–3:40 / 120초**

[영상 재생 중 별도 발화 없음. 도입은 앞 슬라이드에서 연결합니다.]

### 7페이지 · 세 기술의 역할

**3:40–4:25 / 45초**

세 기술은 하나의 영상에 서로 다른 근거를 연결합니다. 모바일 신분증은 등록자의 개인 신원을 확인합니다. 블록체인은 영상 대표값과 등록 이력을 기록해 검증 때 다시 대조합니다. Open DID는 그 등록 건의 보증서를 발급하고 유효성과 연결 정보를 확인합니다. 따라서 콘텐츠가 같아도 등록 증거가 유효하지 않으면 인증하지 않습니다. 기관 소속과 공식 발행 권한은 별도 확인이 필요합니다.

### 8페이지 · 검증 원리

**4:25–5:20 / 55초**

검증은 콘텐츠 대조와 등록 증거 확인, 두 조건입니다. 같은 파일은 전체 해시로 확인합니다. 재인코딩본은 지각해시로 후보를 찾고, 영상과 음성 지문이 같은 원본 시간 위치에 대응하는지 비교합니다. 이어 활성 온체인 기록과 보증서의 유효성, 영상 대표값과 등록자 등 연결 정보를 확인합니다. 모두 통과해야 인증합니다. VC가 없거나 Open DID 검증이 불가능하면 인증하지 않으며, 정확 일치와 유사도 기준 통과도 구분합니다.

### 9페이지 · 차별성

**5:20–5:55 / 35초**

C2PA는 출처와 편집 이력을 검증하는 표준이고, 탐지 AI는 조작 가능성을 분석합니다. 진본은 본인확인된 등록자의 기준 영상과 대조하고, 블록체인 기록과 보증서까지 확인합니다. 차별점은 국내 본인확인부터 시민의 크롬·웹·카카오톡 검증까지 하나의 흐름으로 연결한 점입니다. 기존 출처 표준과도 함께 활용할 수 있는 방향으로 발전시키겠습니다.

### 10페이지 · 도입 가치

**5:55–6:45 / 50초**

첫 도입 대상은 공공기관의 홍보·공보 부서입니다. 공식 링크는 기준 영상을 안내할 수 있습니다. 진본은 시민이 받은 파일이나 유통 영상을 그 등록 영상과 직접 대조하게 합니다. 담당자와 시민이 같은 근거로 확인하도록 하는 것이 구매 가치입니다. 수익 모델은 기관 라이선스와 추가 API 사용량 과금, 시민 기본 검증은 무료 제공 방향입니다. 실제 구매 의향과 업무시간, 운영비는 PoC에서 측정하고 기관 발행 권한도 보완하겠습니다.

### 11페이지 · PoC 계획

**6:45–7:25 / 40초**

다음 단계는 기관 한 곳의 실제 업무에서 검증하는 것입니다. 먼저 담당자 인터뷰로 확인 업무와 구매 기준을 파악하고, 기관 확인과 발행 권한 관리를 설계합니다. 이후 실제 영상으로 재인코딩과 편집, 미등록 사례를 비교합니다. 등록과 확인에 걸리는 업무시간, 잘못 승인하거나 놓치는 사례, 처리시간과 건당 비용을 측정해 도입 여부를 판단하겠습니다. 4분기 PoC 한 곳을 목표로 합니다.

### 12페이지 · 마무리

**7:25–7:40 / 15초**

진본은 누가 등록했는지, 무엇과 일치하는지, 그 근거가 유효한지를 연결합니다. 공유된 영상을 확인할 수 있는 근거, 진본으로 만들겠습니다. 감사합니다.

## 최종 리허설

1. 실제 시연 영상 120초와 오디오를 확인합니다.
2. 발표자 화면에서 2페이지를 넘기고 13~15페이지가 본 발표에 재생되지 않는지 확인합니다.
3. 영상 포함 8분 이내로 리허설합니다. 넘칠 경우 화면을 읽는 말을 줄이고, 기술·구매 가치의 핵심 문장을 남깁니다.
4. 제출할 PowerPoint 파일에서도 동영상 재생과 글꼴을 확인합니다.
