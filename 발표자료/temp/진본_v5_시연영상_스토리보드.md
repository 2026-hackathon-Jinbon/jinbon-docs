# 진본 v5 · 결선 시연 영상 스토리보드

2026 블록체인 해커톤 결선 · 타닥타닥 · 작성 2026-09-18

**120초 동안 ‘발표자가 기준을 등록하고, 시민이 받은 영상을 확인하는 과정’을 실제 앱 화면으로 보여줍니다.**

이 문서는 촬영·편집 계획입니다. 실제 MP4와 검증 결과는 아직 포함하지 않았습니다. 정상·음성 교체 영상의 결과 측정과 VC 발급 전후 화면 녹화는 담당자가 진행합니다. 아래 `[실제 결과 삽입]`은 측정 후 확정하며, 최종 영상에 편집 지시문이 남지 않도록 합니다.

## 1. 전달할 메시지

> 같은 얼굴의 영상이어도 말은 달라질 수 있습니다. 진본은 본인확인된 등록자의 영상과 대조하고, 블록체인 기록과 해당 등록 건의 VC까지 확인합니다.

- **모바일 신분증:** 등록하는 사람의 본인확인. 시장 직함이나 기관의 공식 발행 권한을 인증하는 것은 아닙니다.
- **블록체인:** 영상 대표값과 등록자 DID 등 등록 증거를 기록하고 대조. 영상 파일 자체를 올리는 것은 아닙니다.
- **Open DID · VC:** 해당 등록 건에 연결된 보증서를 발급하고 유효성을 확인. VC가 없으면 인증 완료가 될 수 없습니다.
- **시민의 행동:** 크롬에서 보던 영상, 웹으로 받은 파일, 카카오톡으로 받은 링크를 검증합니다.

시연의 결론은 ‘모든 가짜를 판별한다’가 아니라 **‘등록된 영상과 비교할 근거를 제공한다’**입니다. 인증 결과가 발언 내용의 사실성까지 보증하지는 않습니다.

## 2. 촬영할 두 영상

### A · 가상의 새빛시장 공식 발표

> “청년 월세 지원은 내년에도 계속됩니다. 신청 절차를 간소화해 더 많은 청년이 지원받을 수 있도록 하겠습니다.”

### B · 동일 화면에 음성을 교체한 시연본

> “청년 월세 지원은 올해를 끝으로 중단됩니다. 내년부터는 신규 신청과 기존 수급자에 대한 지원을 모두 종료하겠습니다.”

**A만 기준 영상으로 등록합니다.** B는 A의 화면을 유지하고 음성 트랙만 교체합니다. 두 파일의 길이·해상도·프레임 구성을 맞추고, 공통 길이는 두 대사를 자연스럽게 읽을 수 있도록 정합니다. 길이를 맞추려고 음성 속도를 과하게 높이지 않습니다.

팀원 등 촬영에 동의한 인물이 시장 역할을 맡습니다. 모바일 신분증은 실제 시연자의 신원으로 인증합니다. 가상의 이름이나 직함을 실제 신분증 화면에 합성하지 않습니다.

화면 한쪽에 **“가상 인물·가상 정책 / 시연용”**을 계속 표시합니다. 영상 비교 장면에는 A는 `등록 원본`, B는 `음성 교체본 · 시연 제작물`로 구분합니다. B의 제작 라벨은 진본이 반환한 판정과 별개입니다.

### 오프닝의 길이 결정

두 발언을 모두 낭독하면 앱 시연 시간이 줄어듭니다. **120초 본편에는 첫 문장만 재생**하고, 전체 대사는 A·B 촬영 원본과 발표 문제 설명에 활용합니다. 영상은 앞 PPT의 문제 제기를 이어받는 구성입니다.

## 4. 장면별 촬영·편집 지시

### 01. “내년부터 지원이 끊긴다고?” · 00:00–00:08

**화면·행동**

- 0–2초: 시민이 받은 영상과 “내년부터 월세 지원 중단?”이라는 시연용 메시지.
- 2–6초: B의 첫 문장 “청년 월세 지원은 올해를 끝으로 중단됩니다.” 재생.
- 6–8초: 같은 영상 위에 시민의 질문을 남깁니다.

**자막**

> 같은 얼굴, 달라진 말. 무엇을 확인해야 할까요?

**음성**

영상 속 발언만 사용합니다. 별도 내레이션을 겹치지 않습니다.

**편집 포인트**

메시지는 이야기 도입용 연출 화면으로 만들 수 있으나, 이후 카카오톡의 실제 검증 응답과 혼동되지 않도록 분리합니다. B에는 `음성 교체본 · 시연 제작물`을 표시합니다.

### 02. 공개 전, 기준을 남깁니다 · 00:08–00:12

**화면·행동**

`발표 영상을 공개하기 전` 자막과 함께 A의 첫 문장 “청년 월세 지원은 내년에도 계속됩니다.”를 재생합니다.

**자막**

> 발표자가 먼저, 비교할 기준을 남깁니다

**음성**

A의 발언만 사용합니다.

**편집 포인트**

첫 두 장면을 같은 구도로 연결합니다. 4초에 자연스럽게 읽히지 않으면 발언의 앞뒤 무음을 줄입니다. 등록 대상은 여기서 보여준 A 전체 원본입니다.

### 03. 앱에서 본인확인 · 00:12–00:26

**화면·행동**

- 12–15초: 진본 앱의 본인확인 시작.
- 15–21초: 모바일 신분증 앱 전환 → 동의·인증 동작.
- 21–26초: 진본으로 복귀 → 본인확인 및 등록자 DID 연결 상태.

**자막**

> 모바일 신분증으로 본인확인
>
> 확인된 신원과 등록자 DID 연결

**내레이션**

> “발표자는 진본 앱에서 모바일 신분증으로 본인확인을 합니다. 확인된 신원을 등록자 DID, 즉 디지털 식별자와 연결합니다.”

**촬영 포인트**

세로 화면의 비율을 유지하고 옆에 짧은 설명을 배치합니다. PIN·주민등록번호·CI 등은 가리되 앱 전환과 완료 상태는 보이게 합니다. 작은 보조 문구로 `개인 본인확인 · 기관 권한 확인은 별도`를 표시합니다. 실제 제품의 단계 순서가 다르면 녹화 흐름에 맞춰 컷 순서를 조정합니다.

### 04. 영상 대표값의 블록체인 등록 · 00:26–00:40

**화면·행동**

- 26–30초: A의 썸네일·파일명을 확인하고 등록을 시작.
- 30–35초: 실제 등록 진행 화면.
- 35–40초: 등록 결과에서 영상 제목과 거래 정보 또는 등록 시각을 확대.

**자막**

> 영상의 디지털 지문 → 대표값·등록자 DID 기록

**내레이션**

> “공개할 원본을 선택합니다. 영상의 디지털 지문을 만들고, 대표값과 등록자 DID를 블록체인에 기록합니다.”

**촬영 포인트**

보조 문구는 `영상 파일 자체는 체인에 저장하지 않음`. 거래 식별자는 실제 값을 쓰고 모두 읽게 할 필요는 없습니다. 긴 처리 대기만 잘라내고 `대기 구간 편집`을 표시합니다. 편집된 14초를 처리 성능으로 설명하지 않습니다.

### 05. 체인 등록만으로는 인증되지 않습니다 · 00:40–00:46

**화면·행동**

VC 발급 전 A를 검증한 실제 결과로 전환합니다. 첫 1초에 `보증서 발급 전`, 이후 5초는 결과 문구를 확대해 읽을 시간을 줍니다. 입력 과정 전체는 원본 녹화에 남깁니다.

**자막**

> VC 발급 전 · [실제 결과 삽입]

**내레이션**

> “체인에 등록했어도, VC 보증서가 없으면 인증되지 않습니다.”

**촬영 포인트**

코드상 VC 미발급 상태는 체인 검증이 정상일 때 `CERTIFICATE_MISSING`입니다. 실제 화면이 서비스 연결 오류라면 VC 필수 조건을 증명하는 장면으로 사용할 수 없습니다. 오류 원인을 해결한 뒤 다시 촬영하거나 실제 오류임을 명시합니다. **발급 전과 발급 후는 동일한 등록 건 A를 사용합니다.**

### 06. Open DID VC 발급 · 00:46–01:00

**화면·행동**

- 46–50초: 앱의 A 등록 상세에서 보증서 발급 시작.
- 50–55초: 실제 Wallet 동의·인증 흐름.
- 55–60초: 수령 완료와 A에 연결된 보증서 정보 확대.

**자막**

> Open DID · 이 등록 건에 연결된 VC 발급

**내레이션**

> “이 등록 건의 VC, 디지털 보증서를 Open DID로 발급받습니다. 검증할 때는 유효한 보증서인지, 이 등록 정보와 연결되는지도 확인합니다.”

**촬영 포인트**

VC 발급 성공 여부와 제목·등록 정보의 연결을 실제 화면으로 보여줍니다. 다른 영상의 VC나 과거 결과 화면을 사용하지 않습니다. 복잡한 JSON 전체는 보여주지 않고 읽을 수 있는 제목·상태 위주로 확대합니다.

### 07. 크롬에서 정상 유통본 검증 · 01:00–01:16

**화면·행동**

- 60–64초: 플랫폼에 게시된 A의 URL과 영상 → Chrome 확장 실행.
- 64–68초: 검증 요청과 진행.
- 68–76초: 실제 결과·체인·VC 상태를 확대해 유지.

**자막**

> Chrome · 보고 있는 영상을 바로 검증
>
> 등록 영상 대조 + 블록체인 + VC

**내레이션**

> “시민은 보던 영상에서 크롬 확장을 실행합니다. 등록 영상과 대조하고, 체인 기록과 보증서를 함께 확인합니다.”

**결과 삽입란**

> A 최종 판정: [실제 결과 삽입]
>
> 일치 방식 / 체인 / VC: [실제 결과 삽입]

**촬영 포인트**

플랫폼 변환을 거친 A 유통본의 실제 결과를 사용합니다. 파일의 정확 일치와 영상·음성 유사 비교를 혼동하지 않습니다. 완료 화면의 핵심 근거가 실제 UI에 없으면, UI를 합성하지 말고 확인된 사실만 별도 설명 자막으로 표시합니다.

### 08. 같은 화면에 다른 음성을 넣으면? · 01:16–01:36

**화면·행동**

- 76–80초: B 첫 문장 일부와 `같은 화면 · 바뀐 음성` 표시.
- 80–85초: A와 동일한 Chrome 검증 절차 실행.
- 85–92초: 실제 최종 판정 및 제공되는 영상·음성 비교 근거 확대.
- 92–96초: A와 B의 실제 결과를 나란히 정리.

**기본 내레이션**

> “이번에는 같은 화면에 음성만 바꾼 영상입니다. 같은 방식으로 검증하고, 실제 비교 결과를 확인합니다.”

이후 1문장은 아래 ‘결과별 마무리 대사’에서 **측정 결과에 맞는 것 하나만** 사용합니다. 위 기본 대사와 함께 녹음해 20초를 넘지 않는지 확인합니다.

**자막·결과 삽입란**

> B 최종 판정: [실제 결과 삽입]
>
> 영상·음성 비교 근거: [실제 결과 삽입]

**편집 포인트**

‘음성 교체본’은 제작 사실이고 ‘미인증’ 등은 검증 결과입니다. 두 라벨을 구분합니다. 인증 실패를 곧바로 ‘가짜 확정’으로 바꾸지 않습니다. 비교 정보가 없는 응답에 임의의 음성 점수나 빨간 경고 배지를 추가하지 않습니다.

### 09. 웹과 카카오톡에서도 · 01:36–01:52

**웹 · 96–104초**

- 3초: 웹에서 A 원본 파일 선택·검증 요청.
- 5초: 실제 결과 유지.
- 자막: `웹 · 받은 파일 업로드`

**카카오톡 · 104–112초**

- 3초: 진본 채널에 A 유통본 링크 전송.
- 5초: 실제 응답 유지.
- 자막: `카카오톡 · 영상 링크 전송`

**내레이션**

> “웹에서는 받은 파일을 올리고, 카카오톡에서는 영상 링크를 보냅니다. 익숙한 채널에서 등록된 근거를 확인합니다.”

**결과 삽입란**

> 웹 A: [실제 결과 삽입] / 카카오톡 A: [실제 결과 삽입]

**촬영 포인트**

두 채널의 결과 영역은 최소 5초씩 유지합니다. 웹의 파일 검증과 카카오톡의 URL 검증이 동일한 입력·일치 방식이라고 표현하지 않습니다. 화면비가 다른 두 화면을 동시에 작게 놓기보다 차례로 크게 보여줍니다.

### 10. 공유하기 전, 확인할 근거 · 01:52–02:00

**화면·행동**

- 112–117초: 도입의 시민 장면으로 돌아와 `공유하기 전에 등록된 근거부터 확인합니다` 표시.
- 117–120초: 진본 로고와 마지막 문장 유지.

**자막·내레이션**

> “발표자는 기준을 남기고, 시민은 공유 전에 확인합니다. 영상에 확인할 근거를 연결하는 진본입니다.”

**편집 포인트**

도입에서 받은 메시지에 실제로 답장을 보낼 필요는 없습니다. B의 결과가 무엇이든 사실에 맞는 마무리입니다. ‘시장이 직접 인증한 공식 발표’처럼 기관 권한까지 확인된 것으로 표현하지 않습니다.

## 5. 실제 결과에 따른 마무리 대사

아래 내부 판정명은 촬영 담당자의 확인용입니다. 관객에게는 제품의 실제 결과 문구와 쉬운 설명을 보여줍니다.

| 확인된 실제 상태 | 사용할 대사 | 피할 표현 |
|---|---|---|
| B가 음성 비교 기준 미달이며 해당 근거가 확인됨 | “음성 비교 기준을 충족하지 못해 인증되지 않았습니다.” | “모든 음성 조작을 탐지합니다.” |
| `CONTENT_SIMILAR` 또는 `PARTIAL_MATCH`, 음성 원인은 불명확 | “등록 영상과 유사하지만, 원본 일치까지 확인하지 못했습니다.” | “음성 조작이 확정됐습니다.” |
| `NOT_REGISTERED` | “대조할 등록 기록을 찾지 못했습니다. 미등록만으로 가짜라고 판단할 수는 없습니다.” | “가짜 영상입니다.” |
| `CERTIFICATE_MISSING` | “등록 기록은 있지만 VC 보증서가 없어 인증되지 않았습니다.” | “영상이 조작됐습니다.” |
| `CERTIFICATE_INVALID` | “보증서가 유효하지 않거나 이 등록 건과 연결되지 않아 인증되지 않았습니다.” | “내용이 거짓입니다.” |
| `VERIFICATION_UNAVAILABLE` | “검증을 완료하지 못했습니다. 현재 상태로는 진위를 판단할 수 없습니다.” | “조작 영상이라 차단됐습니다.” |
| B가 인증됨 | “이 사례의 음성 변경은 현재 비교 기준으로 구분하지 못했습니다.” | 실패 결과를 성공 화면으로 교체 |

`VERIFICATION_UNAVAILABLE`은 외부 연결 실패뿐 아니라 체인 무결성 확인 실패에서도 나올 수 있습니다. 원인은 실제 메시지로 확인합니다. VC 발급 전 장면은 체인 확인이 정상인 상태에서 미발급 판정을 확보해야 VC의 필요성을 설명할 수 있습니다.

**A가 인증되지 않거나 B가 인증되는 경우:** 완성 영상의 성공 사례로 단정해 제출하지 않습니다. 실제 결과를 기록하고 원인 분석·개선 후 재촬영하거나, 현 상태의 한계를 설명하는 시연으로 대본을 확정합니다. 근거 없는 결과 합성은 하지 않습니다.

## 6. 필요한 앱과 소재

### 앱·서비스

- 진본 모바일 앱: 본인확인, A 등록, 등록 상세, VC 발급 흐름.
- 모바일 신분증 앱: 실제 본인확인과 진본 복귀.
- 사용 중인 Open DID Wallet: 실제 동의·수령 흐름. 진본 앱 내부 기능이라면 실제 구조대로 촬영.
- Chrome + 진본 확장: A와 B를 같은 절차로 검증.
- 지원되는 영상 플랫폼: A·B URL 준비 및 플랫폼 처리 완료.
- 진본 웹: A 파일 업로드 검증.
- 카카오톡 진본 채널: A 링크 전송·실제 응답.
- 동작 중인 백엔드·블록체인·Open DID 연동: 결과 측정 전 상태 확인.

### 파일·그래픽

| 소재 | 파일명 예시 | 비고 |
|---|---|---|
| 정상 발표 전체 원본 | `A_original.mp4` | 기준 등록 대상, 이후 파일 변경 금지 |
| 음성 교체본 | `B_audio_replaced.mp4` | A의 화면 유지, 별도 등록하지 않음 |
| 정상·변경본 URL 기록 | `demo_urls.txt` | 어느 URL이 A/B인지 명확히 구분 |
| 앱 화면 원본 녹화 | `01_identity` / `02_registration` / `03_vc` | 편집 전 녹화도 보관 |
| VC 전후 검증 녹화 | `04_before_vc` / `05_after_vc` | 동일 등록 건·동일 입력으로 비교 |
| 시민 검증 녹화 | `06_chrome_A` / `07_chrome_B` / `08_web` / `09_kakao` | 결과·근거까지 녹화 |
| 진본 로고 | 기존 공식 로고 파일 | PPT와 같은 자산 사용 |
| 내레이션 | 장면별 별도 음성 파일 | 결과 의존 문장은 측정 후 녹음 |
| 실제 결과 기록 | 아래 기록표 | 녹화 시점과 UI·응답 일치 확인 |

공개 URL 게시 여부와 범위는 촬영 담당자가 정합니다. 가상 상황임을 영상과 게시 설명에 명시합니다. 이 문서 작성 작업에서는 게시·전송·촬영을 실행하지 않았습니다.

## 7. 촬영 순서와 결과 기록표

편집 순서와 달리 **VC 발급 전 녹화를 먼저 확보해야 합니다.** 발급 후 결과를 발급 전처럼 연출할 수 없습니다.

1. A·B 파일을 확정하고 A/B URL의 처리가 끝났는지 확인합니다.
2. 실제 본인확인·DID 연결 화면을 녹화합니다.
3. A만 등록하고 영상 ID·등록 시각·거래 정보를 기록합니다.
4. VC 발급 전에 A 검증을 녹화합니다. 기존 결과 캐시 등으로 상태가 다르게 보이지 않는지 확인합니다.
5. 같은 등록 건의 VC 발급·수령을 녹화합니다.
6. 동일한 A 입력으로 발급 후 검증을 녹화합니다.
7. Chrome A → Chrome B → 웹 A → 카카오톡 A 순서로 실제 결과를 확보합니다.
8. 실제 결과에 맞춰 자막과 마지막 내레이션 문장을 확정합니다.

| 입력·시점 | 최종 판정 | 체인 / VC / 연결 확인 | 비교 방식·근거 | 녹화 파일 |
|---|---|---|---|---|
| A · VC 발급 전 | [실제 결과 삽입] | [실제 결과 삽입] | [실제 결과 삽입] | [입력] |
| A · VC 발급 후, 같은 입력 | [실제 결과 삽입] | [실제 결과 삽입] | [실제 결과 삽입] | [입력] |
| Chrome · A URL | [실제 결과 삽입] | [실제 결과 삽입] | [실제 결과 삽입] | [입력] |
| Chrome · B URL | [실제 결과 삽입] | [실제 결과 삽입] | [실제 결과 삽입] | [입력] |
| 웹 · A 파일 | [실제 결과 삽입] | [실제 결과 삽입] | [실제 결과 삽입] | [입력] |
| 카카오톡 · A URL | [실제 결과 삽입] | [실제 결과 삽입] | [실제 결과 삽입] | [입력] |

UI에 없는 상세 근거는 실제 응답·로그에서 촬영 담당자가 확인해 기록합니다. 민감한 원문 로그를 발표 영상에 넣을 필요는 없습니다.

## 8. 촬영·편집 체크리스트

### 녹화 전

- [ ] A만 등록하고 B를 기준 영상으로 등록하지 않았다.
- [ ] A·B 화면은 같고 음성만 바뀌었는지 확인했다.
- [ ] 신원 인증에 사용할 실제 시연자와 시장 역할의 관계를 정리했다.
- [ ] 모바일 신분증·Wallet·Chrome 확장·웹·카카오톡의 실제 동작을 확인했다.
- [ ] VC 발급 전후를 같은 등록 건으로 녹화할 준비가 됐다.
- [ ] 알림과 개인 대화를 가리고 결과를 읽을 수 있는 화면 배율을 정했다.

### 편집 중

- [ ] 가상 인물·가상 정책·시연용 표시가 보인다.
- [ ] 제품 화면의 판정·배지·점수를 합성하지 않았다.
- [ ] 결과에 의존하는 대사는 실제 측정 결과와 일치한다.
- [ ] 본인확인을 기관 권한 인증으로 설명하지 않았다.
- [ ] 체인 등록을 영상 파일 저장으로 표현하지 않았다.
- [ ] VC 필수 조건과 해당 등록 정보와의 연결이 드러난다.
- [ ] 결과 화면은 읽을 시간을 유지하고 긴 대기만 편집했다.
- [ ] 미등록·비인증·검증 불가를 가짜 판정으로 바꾸지 않았다.

### 출력·발표 전

- [ ] 최종 타임라인이 120초이고 음성은 겹치지 않는다.
- [ ] `[실제 결과 삽입]` 등 편집 지시문이 최종 영상에 남지 않았다.
- [ ] 개인정보·PIN·CI·토큰·관련 없는 알림이 보이지 않는다.
- [ ] 1920×1080, 16:9, MP4(H.264 + AAC), 30fps로 출력했다.
- [ ] 1080p 기준 핵심 자막 약 40px 이상, 두 줄 이내이며 결과 UI도 확대했다.
- [ ] 발표 환경에서 소리·권한·재생을 확인하고 로컬 MP4를 별도 보관했다.
- [ ] 실제 발표 리허설로 전체 8분 이내인지 확인했다.

## 9. 시간이 넘칠 때 줄이는 순서

**우선 120초 기본안을 유지합니다.** 녹음·녹화 후 시간이 넘치면 오프닝 메시지나 전환 효과를 먼저 줄입니다. 신분증 완료·VC 수령·검증 결과를 빠르게 돌려 읽지 못하게 하지 않습니다.

110초 축약이 꼭 필요할 때는 다음처럼 줄일 수 있습니다.

| 장면 | 기본 | 축약 | 조정 |
|---|---:|---:|---|
| 도입 + 정상 발언 | 12초 | 8초 | 앞 PPT에서 문제 설명 후 발췌 대비만 재생 |
| 본인확인 | 14초 | 14초 | 유지 |
| 등록 | 14초 | 12초 | 파일 선택 전환 2초 축약 |
| VC 발급 전 | 6초 | 6초 | 유지 |
| VC 발급 | 14초 | 14초 | 유지 |
| Chrome A | 16초 | 14초 | 실행 전환 2초 축약, 결과 8초 유지 |
| Chrome B | 20초 | 20초 | 유지 |
| 웹 + 카카오톡 | 16초 | 16초 | 유지 |
| 엔딩 | 8초 | 6초 | 로고 전환 2초 축약 |
| **합계** | **120초** | **110초** | **절약 10초** |

- **물리적 6번 슬라이드**에 120초 시연 영상 영역이 있습니다. 오른쪽 세 단계 설명은 유지합니다.
- 영상 영역: **X 40pt / Y 139pt / W 650pt / H 365.625pt**, 16:9.
- 교체 대상: 배경 `p10_i233`, 중앙 문구 `p10_i234`, 설명 문구 `p10_i235`. 중앙의 텍스트는 2개입니다.
- 발표 시간표에서 영상은 **01:40–03:40**입니다. 전체는 7분 40초 계획에 여유 20초이며, 실제 리허설로 확인해야 합니다.

**재생 직전 발표자 한 문장**

> “발표자가 기준을 남기고, 시민이 받은 영상을 확인하는 과정을 보시겠습니다.”

**재생 직후 기술 페이지로 연결**

> “방금 과정은 세 가지를 연결합니다. 누가 등록했는지, 무엇을 기록했는지, 어떤 보증서를 확인하는지입니다.”

영상 중 현장 발표자의 설명은 겹치지 않습니다. 영상이 재생되지 않으면 슬라이드 오른쪽 세 단계로 요약하고 기술 설명으로 이어갑니다. 확인하지 않은 성공 결과를 말로 대신 만들지 않습니다.
