# 서비스 개요

## 해결하려는 문제

영상은 복제와 재인코딩이 쉽습니다. 어떤 영상이 원본인지, 누가 언제 그것을 공개했는지를
영상 파일만 봐서는 알 수 없습니다. 편집·자막·재업로드를 거치면 파일 자체가 달라지므로
단순 파일 비교로는 "같은 영상"인지도 판단하기 어렵습니다.

진본은 이 문제를 두 갈래 증명으로 나눠 다룹니다.

| 증명 | 질문 | 수단 |
|---|---|---|
| **무결성 증명** | 이 영상이 등록 당시와 같은 영상인가 | 해시 + 블록체인 기록 |
| **신뢰성 증명** | 누가 언제 이것을 등록했는가 | DID + VC 보증서 |

무결성은 블록체인이 담당하고, 신뢰성은 Open DID가 담당합니다.
진본 여부의 최종 판정은 **블록체인 검증을 중심**으로 하며,
VC는 등록자가 보유하고 다른 서비스에 제출할 수 있는 디지털 인증서 역할을 합니다.

## 두 종류의 해시

진본이 "같은 영상"을 판단하는 방식은 두 층으로 되어 있습니다.

- **fineHash** — 파일 전체의 SHA-256. 바이트 단위로 동일한 원본인지 확인합니다.
- **perceptualHash** — 프레임에서 뽑은 DCT 기반 지각해시. 재인코딩·리사이즈·압축을 거쳐도
  비슷한 값이 나오므로, 파일이 달라져도 **내용이 같은 영상**을 찾아냅니다.

두 해시를 이어 붙여 SHA-256을 한 번 더 계산한 값이 **merkleRoot**이고,
블록체인에 기록되는 것은 이 merkleRoot입니다. 영상 원본 파일은 서버에 저장하지 않습니다.

## 사용자

### 공인 등록자 (ISSUER)
모바일 신분증으로 본인확인을 마치고 Wallet DID를 연결한 회원입니다.
원본 영상을 등록하고, 블록체인 기록과 VC 보증서를 발급받을 수 있습니다.
가입을 완료하면 자동으로 `ISSUER` 역할이 부여됩니다.

### 비회원 검증자
가입이나 로그인 없이 영상을 검증할 수 있습니다.
공개 검증 결과만 볼 수 있고, 등록자의 개인정보나 Wallet에는 접근할 수 없습니다.

## 채널별 역할

| 채널 | 저장소 | 역할 | 로그인 |
|---|---|---|---|
| iOS 앱 | `jinbon-ios` | 가입·로그인, DID/Wallet 관리, 영상 등록, 보증서 보관 | 필요 (검증만 예외) |
| 웹 | `jinbon-web` | 파일 업로드 기반 영상 검증 | 불필요 |
| Chrome 확장 | `jinbon-extension` | 시청 중인 영상의 URL 기반 즉시 검증 | 불필요 |
| 백엔드 | `jinbon-backend` | 위 세 채널의 공통 API, 외부 연동 허브 | — |

앱에도 검증 기능이 있지만 앱의 중심은 **등록자용 Wallet과 원본 영상 관리**입니다.
검증의 주 채널은 웹과 확장입니다.

## 해커톤 과제 대응

2026 블록체인 & AI 해커톤 Track 2(MVP 개발) 과제에 다음과 같이 대응합니다.

| 과제 | 기술 | 진본에서의 역할 |
|---|---|---|
| 필수 | OmniOne CX 모바일 신분증 | 등록자 본인확인 및 로그인 |
| 선택 1 | Open DID | 영상 블록체인 등록 사실을 보증하는 VC 발급·검증 |
| 선택 2 | OmniOne Chain | 영상 해시(merkleRoot)의 온체인 기록 및 무결성 검증 |

두 선택과제는 서로 다른 질문에 답합니다.
OmniOne Chain은 "**이 영상이 변조되지 않았는가**", Open DID는 "**누가 언제 이 기록을 만들었는가**"입니다.

## 등록과 발급의 분리

영상의 블록체인 등록과 VC 보증서 발급은 **별개의 단계**입니다.
등록이 성공하면 VC 발급을 나중으로 미루거나 실패해도 등록 결과는 그대로 유지되고,
이후 Wallet에서 다시 발급받을 수 있습니다.

이 설계 덕분에 Open DID Orchestrator가 꺼져 있는 환경(`OPENDID_ENABLED=false`)에서도
영상 등록과 블록체인 기록, 검증은 정상 동작합니다. 이때 `vcVerified`는 항상 `false`입니다.
