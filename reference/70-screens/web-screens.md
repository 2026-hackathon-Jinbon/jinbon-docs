# 웹 화면 기획서

`jinbon-web`의 현재 구현 화면 명세입니다.
모든 문구는 `app/page.tsx`에 있는 그대로입니다.

## 구조

라우트는 `/` 하나이고 화면 전체가 `app/page.tsx`의 `Home` 컴포넌트입니다.
페이지 이동 없이 상태에 따라 중앙 영역만 바뀝니다.

```
<main>
  ├── header.site-header      항상 표시
  ├── section.hero            항상 표시
  │     └── div.verifier-shell
  │           ├── div.step-rail       3단계 표시
  │           └── 워크스페이스 또는 결과 패널  ← 여기가 전환됨
  ├── section.trust-strip     항상 표시
  └── footer                  항상 표시
</main>
```

## 상시 노출 영역

### 헤더 (`site-header`)

| 요소 | 내용 |
|---|---|
| 브랜드 마크 | `眞` |
| 브랜드명 | `진본` (앵커 `#top`, `aria-label="진본 홈"`) |
| 상태 표시 | `블록체인 검증 네트워크 연결됨` |

> 상태 표시는 실제 연결 상태를 확인하지 않는 **정적 문구**입니다.
> 백엔드가 꺼져 있어도 그대로 표시됩니다.

### 히어로 (`hero`)

| 요소 | 내용 |
|---|---|
| Eyebrow | `ORIGINALITY, VERIFIED` |
| 제목 | `이 영상은` / `진짜일까요?` (두 번째 줄은 `<em>`) |
| 본문 | `영상을 올리면 원본 해시와 블록체인 기록, 디지털 자격증명을 교차 검증해 등록된 진본 여부를 확인합니다.` |

### 단계 표시 (`step-rail`)

`aria-label="검증 단계"`

| 단계 | 라벨 | `active` 조건 | `done` 조건 |
|---|---|---|---|
| 01 | 영상 선택 | `result == null` | `result != null` |
| 02 | 무결성 분석 | `isVerifying` | `result != null` |
| 03 | 결과 확인 | `result != null` | — |

### 신뢰 안내 (`trust-strip`)

`aria-label="검증 방식"`

| 번호 | 제목 | 설명 |
|---|---|---|
| 01 | 파일 지문 생성 | 원본 파일과 프레임의 고유한 해시를 계산합니다. |
| 02 | 분산 원장 대조 | 변경 불가능한 블록체인 등록 기록을 조회합니다. |
| 03 | VC 교차 검증 | 발급자의 OpenDID 자격증명 유효성을 확인합니다. |

### 푸터

`© 2026 JINBON` / `기술로 증명하는 콘텐츠의 진실`

## W-01 검증 홈 (초기)

**조건** `result == null && file == null`

**드롭존** (`drop-zone`)

| 요소 | 내용 |
|---|---|
| 심볼 | `↑` |
| 제목 | `확인할 영상을 올려주세요` |
| 설명 | `여기로 끌어다 놓거나 눌러서 파일 선택` |
| 규격 안내 | `MP4 · MOV · AVI · 최대 100MB` |

전체가 `<button>`이며 클릭 시 숨겨진 `<input type="file" accept="video/*">`를 엽니다.
드래그 오버 시 `dragging` 클래스가 붙습니다.

**하단 액션 행** (`action-row`)

| 요소 | 내용 |
|---|---|
| 개인정보 안내 | `✓ 영상 원본은 서버에 저장되지 않습니다.` |
| 검증 버튼 | `진본 여부 확인하기 →` (파일 없으면 `disabled`) |

## W-02 영상 선택됨

**조건** `file != null && result == null`

드롭존이 미리보기로 바뀝니다.

| 요소 | 내용 |
|---|---|
| 영상 | `<video controls preload="metadata">`, `URL.createObjectURL(file)` |
| 파일 아이콘 | `▶` |
| 파일명 | `file.name` |
| 파일 정보 | `{크기} · {타입 또는 video}` |
| 제거 버튼 | `×` (`aria-label="선택한 영상 제거"`) |

파일 크기 표기 규칙:

```
1MB 미만  →  "{n} KB"   (최소 1KB로 반올림)
1MB 이상  →  "{n.n} MB" (소수점 1자리)
```

**검증 버튼 상태**

| 상태 | 표시 |
|---|---|
| 대기 | `진본 여부 확인하기 →` |
| 진행 중 | 스피너 + `진본 기록 대조 중` (`disabled`) |

**오류 메시지** (`error-message`, `role="alert"`)

| 상황 | 문구 |
|---|---|
| 영상이 아닌 파일 | `영상 파일만 선택할 수 있습니다.` |
| 100MB 초과 | `파일 크기는 최대 100MB까지 가능합니다.` |
| 백엔드 연결 불가 | `검증 서버에 연결할 수 없습니다. 백엔드가 8070 포트에서 실행 중인지 확인해 주세요.` |
| 그 외 서버 오류 | 응답의 `message` 또는 `검증 서버가 요청을 처리하지 못했습니다.` |
| 알 수 없음 | `알 수 없는 오류가 발생했습니다.` |

## W-03 검증 결과

**조건** `result != null`

**결과 톤** (`resultTone`)

| 조건 | 톤 | 도장 | 제목 |
|---|---|---|---|
| `authentic && active` | `authentic` | `✓` | `진본으로 확인됐습니다` |
| `verdict == "NOT_REGISTERED"` | `unknown` | `?` | `등록 기록이 없습니다` |
| 그 외 | `warning` | `!` | `주의가 필요한 영상입니다` |

**요약 영역** (`result-summary`)

| 요소 | 내용 |
|---|---|
| 도장 | 톤별 기호 |
| Kicker | `VERIFICATION COMPLETE` |
| 제목 | 톤별 문구 |
| 본문 | 서버 응답의 `message` |

**증거 그리드** (`evidence-grid`)

| 라벨 | 값 | 클래스 |
|---|---|---|
| 블록체인 기록 | `검증 완료` / `확인 안 됨` | `pass` / `fail` |
| 디지털 자격증명 | `VC 유효` / `확인 안 됨` | `pass` / `fail` |
| 등록 상태 | `활성` / `비활성` | `pass` / `fail` |
| 등록 시각 | 한국어 긴 날짜 + 짧은 시각, 없으면 `확인되지 않음` | — |

날짜 형식은 `Intl.DateTimeFormat("ko-KR", { dateStyle: "long", timeStyle: "short" })`입니다.

**발급자 DID 행** (`did-row`) — `issuerDid`가 있을 때만

30자 이상이면 앞 18자와 뒤 8자만 남기고 가운데를 `…`로 줄입니다.
전체 값은 `title` 속성으로 확인할 수 있습니다.

> 라벨은 `발급자 DID`지만 백엔드가 보내는 값은 **영상 등록자의 DID**입니다.
> VC 발급기관 DID가 아닙니다.

**주의 문구** (`result-notice`) — `notice`가 있을 때 `※ {notice}` 형태로 표시

**하단 버튼** — `다른 영상 확인하기` (누르면 상태를 초기화하고 W-01로)

## 판정 표현의 한계

웹은 `verdict` 7종을 개별적으로 구분하지 않고 톤 3종으로만 나눕니다.

| 백엔드 verdict | 웹 표시 |
|---|---|
| `EXACT_MATCH` (검증 통과) | 진본으로 확인됐습니다 |
| `SAME_CONTENT` (검증 통과) | 진본으로 확인됐습니다 |
| `SIMILAR_MATCH` (검증 통과) | 진본으로 확인됐습니다 |
| `NOT_REGISTERED` | 등록 기록이 없습니다 |
| `REGISTERED_BUT_REVOKED` | 주의가 필요한 영상입니다 |
| `CERTIFICATE_INVALID` | 주의가 필요한 영상입니다 |
| `VERIFICATION_UNAVAILABLE` | 주의가 필요한 영상입니다 |

정확 일치와 유사 일치가 같은 문구로 표시되고, `similarityDistance`도 화면에 나오지 않습니다.
서버의 `message`와 `notice`가 그 차이를 설명하는 역할을 합니다.

iOS 앱은 7종을 각각 구분해 표시하므로 같은 영상을 검증해도 웹과 앱의 표현이 다릅니다.
자세한 내용은 [알려진 이슈](../90-status/open-issues.md)를 참고합니다.
